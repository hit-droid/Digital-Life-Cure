- 全屏 App 是「控制台 + 聊天终端」
- 悬浮窗是「智能体本体」（Live2D + 主动行为）

## 2. v1.24.0 详细功能清单

### 2.1 智能体核心增强

#### 2.1.1 工具市场（Tool Market）
**问题**：现在只有 5 个内置工具（set_expression / play_animation / say / get_time / move），太弱
**目标**：打造一个可视化的工具市场，用户可启用/禁用工具，查看工具描述

**实现**：
- 新建 `ToolMarketActivity.java`（~400 行）
- 新建 `app/src/main/java/com/digitallife/tools/ToolMarketAdapter.java`
- 工具分类：表达 / 记忆 / 系统 / 实用 / 信息
- 每个工具显示：图标、名称、描述、使用次数、启用开关
- 内置工具从 5 个扩展到 20+：
  - **表达类**（5）：set_expression, play_animation, say, get_time, move
  - **记忆类**（4）：memory_search（搜索记忆）、memory_recall（主动回忆）、memory_save（保存重要信息）、memory_forget（遗忘）
  - **系统类**（5）：get_battery（电量）、get_location（位置）、get_weather（天气）、set_reminder（提醒）、take_screenshot（截图）
  - **实用类**（4）：web_search（联网搜索）、open_app（打开App）、send_notification（通知）、clipboard（剪贴板）
  - **信息类**（3）：get_calendar（日程）、get_contacts（联系人）、get_files（文件）
- 工具调用权限模型：自动允许 / 每次询问 / 禁用（三级）
- 工具调用历史：每次调用记录到 log，可查看
- 新建 `app/src/main/java/com/digitallife/tools/ToolUsageLog.java` 持久化

#### 2.1.2 计划模式（Plan Mode）
**问题**：当前 LLM 调用是"想到就做"，缺少规划和复盘
**目标**：Agent 能"先思考 → 列出计划 → 逐步执行 → 复盘"

**实现**：
- 新建 `app/src/main/java/com/digitallife/brain/PlanExecutor.java`（~200 行）
- 在 `AgentBrain.java` 中增加 `executePlan(task)` 方法
- LLM 第一轮：理解任务，输出 `{"plan": ["step1", "step2", ...]}`
- 后续每轮：执行一步，输出 `{"current_step": "...", "result": "..."}`
- 全部完成后：复盘 `{"reflection": "..."}` 保存到记忆
- 计划可视化：在 `ChatActivity` 中显示计划卡片（步骤 + 当前进度 + 复盘）

#### 2.1.3 主动行为引擎（Proactive Engine）
**问题**：当前 AICore 30s 循环只是调 LLM 拿行为包，但行为模式单一
**目标**：让角色能"主动想起"——基于时间/事件/记忆触发行为

**实现**：
- 修改 `app/src/main/java/com/digitallife/brain/AICore.java`（扩展 200 行）
- 新增 `ProactiveEngine.java`（~300 行）：
  - **时间触发**：早 8 点说"早安"，晚 22 点说"晚安"
  - **事件触发**：检测到用户离开桌面（PetService 触摸超时 5min）→ 主动发消息
  - **记忆触发**：每 6 小时从记忆中抽取"今日关注点"，融入行为包
  - **情绪触发**：连续 3 次检测到"难过"情绪 → 主动关心
- 所有主动行为必须经过 LLM 生成，不能用模板（避免生硬）
- 新增 `app/src/main/java/com/digitallife/brain/ProactiveLog.java` 记录主动行为历史

#### 2.1.4 Hook Runner（工具拦截器）
**目标**：在工具调用前后插入钩子（用于权限、统计、日志）

**实现**：
- 新建 `app/src/main/java/com/digitallife/tools/HookRunner.java`（~150 行）
- 三个钩子点：`preCall` / `postCall` / `onError`
- 内置钩子：
  - **权限检查**：检查工具的"每次询问"配置
  - **使用统计**：累加 tool_usage_count
  - **日志记录**：记录到 ToolUsageLog
  - **上下文注入**：调用后把结果摘要注入记忆

### 2.2 记忆系统重构

#### 2.2.1 记忆可视化
**问题**：当前 `MemoryManageActivity.java` 只是文本列表，看不出记忆结构
**目标**：让用户看到"她记住了什么"——可浏览、可搜索、可编辑

**实现**：
- 完全重写 `MemoryManageActivity.java`（从 420 行扩展到 ~800 行）
- 新建 `app/src/main/java/com/digitallife/memory/MemoryGraphView.java`（自定义 View，~300 行）：
  - **时间线视图**：按时间轴显示记忆节点
  - **关键词云**：高频词可视化
  - **关系图**：节点之间的关系连线
- 记忆条目支持：标签（tag）、重要度（weight）、来源（auto/manual）、时间
- 搜索：按内容/标签/时间过滤
- 操作：编辑、删除、合并、导出

#### 2.2.2 记忆自动提取
**问题**：当前记忆只是累积对话，没有"学习"
**目标**：每 6 小时用 LLM 自动从记忆中提取关键信息

**实现**：
- 新建 `app/src/main/java/com/digitallife/memory/MemoryExtractor.java`（~250 行）
- 在 `AICore.java` 中注册定时任务（6h 间隔）
- LLM 接收最近的 50 条记忆，输出：
  ```json
  {
    "new_memories": [
      {"content": "用户喜欢喝咖啡", "tags": ["preference"], "weight": 0.7},
      ...
    ],
    "forgotten": ["用户上周的临时想法"]
  }
  ```
- 自动去重 + 合并相似记忆
- 提取结果写入 `MemoryStore` 并触发持久化

#### 2.2.3 混合检索
**问题**：当前记忆注入是"最近 N 条"，太粗糙
**目标**：检索时结合时间 + 关键词 + 重要度

**实现**：
- 修改 `app/src/main/java/com/digitallife/util/MemoryStore.java`（+200 行）
- 新建 `app/src/main/java/com/digitallife/memory/MemoryRetriever.java`（~200 行）：
  - 召回：取最近 20 条 + 关键词匹配 10 条 + 高重要度 5 条
  - 排序：时间衰减 + 重要度加权
  - 注入 LLM system prompt 的"## 记忆"段
- 检索结果可视化：在 `MemoryActivity` 中显示"这次对话用到了哪条记忆"

### 2.3 角色系统（Persona）

#### 2.3.1 角色卡管理
**目标**：支持多角色，每个角色独立人格/模型/记忆

#### 2.3.2 角色切换

## 5. 风险与控制

### 5.1 风险点

| 风险 | 影响 | 缓解 |
|------|------|------|
| 工具数量增加导致 LLM 选错工具 | 中 | 工具描述严格编写 + 默认 5 个核心工具 |
| 主动行为太频繁打扰用户 | 中 | ProactiveEngine 加冷却（同类 1h 内不重复） |
| 多角色切换导致数据混乱 | 高 | 每个角色独立 SharedPreferences 命名空间 |
| 记忆图 View 性能问题 | 中 | 限制单次渲染 200 节点 + Lazy 加载 |
| 计划模式 LLM 成本翻倍 | 中 | 默认关闭，用户可启用 |
| 视觉升级引入性能下降 | 低 | 仅顶栏/侧栏/控制台做精致化，主体页面保持 |

### 5.2 不在 v1.24.0 范围

- 语音对话（→ v1.24.1）
- 多模态（图片理解、文件解析）→ v1.24.1
- 触发器（定时/Tasker）→ v1.24.2
- 图结构记忆（节点关系编辑）→ v1.25.0
- 备份恢复完整化 → v1.24.2
- Web Chat 远程访问 → v1.25.0
